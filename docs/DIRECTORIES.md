# 目录结构与归属

默认使用当前用户的 `~/Developer`，不沿用任何其他电脑的用户名或绝对路径。

```text
~/Developer/
├── machine/             这台机器的规范副本、工具登记和变更记录
├── tools/               自维护工具、固定安装和源码
│   └── <tool-id>/
└── projects/            实际工作，每个项目一个目录
    └── <project-id>/
        ├── input/       原始材料
        ├── work/        工作副本与中间文件
        ├── output/      最终成果
        └── README.md    项目目标、数据位置和继续工作的方法
```

本仓库本身可以放在 `~/Developer/projects/agent-machine-playbook`。它是通用规则的维护源；`machine` 是部署位置及机器状态，不把整个 `machine` 上传到公开仓库。

## 按内容选择位置

| 内容 | 位置或管理方式 |
| --- | --- |
| 桌面应用 | 系统标准应用目录；macOS 通常为 `/Applications` |
| 包管理器安装 | 保留其标准管理位置，不手动挪内部文件 |
| 自维护源码和脚本 | `~/Developer/tools/<tool-id>` |
| 项目专用依赖 | 项目的虚拟环境、依赖目录及锁文件 |
| 独立工具的专用依赖 | 工具自己的隔离环境，登记其归属 |
| macOS 长期应用数据 | `~/Library/Application Support/<工具>` 或该应用的既有约定 |
| macOS 可重建缓存 | `~/Library/Caches/<工具>` 或包管理器约定 |
| macOS 用户后台启动 | `~/Library/LaunchAgents`，登记服务名与实际运行目录 |
| 工具入口包装脚本 | `~/.local/bin`，仅在确有需要时创建 |
| 样本、报告与项目成果 | 项目的 input、work、output；应用管理的成果记录实际位置 |

Linux、Windows 保留相同的归属原则，应用数据、缓存和服务使用对应平台及管理器的标准位置。初始化脚本只创建用户级 Developer 目录，不配置系统服务或假定其他平台也有 macOS 的 Library 布局。

## 整理现有目录

先建立下表，再一次迁移一个工具。数据库、虚拟环境和后台服务不能只靠复制目录完成迁移。

| 内容 | 旧路径 | 新路径 | 当前引用者 | 数据保护方式 | 验收结果 | 旧副本处理条件 |
| --- | --- | --- | --- | --- | --- | --- |
| 待确认工具或项目 | 待核对 | 按实际选择 | 启动脚本、MCP、服务等 | 按应用选择 | 未验证 | 验证后确定 |
