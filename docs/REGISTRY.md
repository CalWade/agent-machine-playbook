# 本机工具登记

通用仓库中的 `templates/tools.json` 是空模板；每台机器在 `~/Developer/machine/tools.json` 维护自己的条目。完整条目示例见 [模板](../templates/tool-entry.json)，示例不是安装要求或可用性声明。

| 文件 | 含义 | 更新方式 |
| --- | --- | --- |
| tools.json | 用途、归属、调用入口、依赖、数据位置、维护方式和验证范围 | Agent 在实际安装和验收后维护 |
| TOOLS.md | 从工具登记生成的阅读索引 | 运行采集脚本生成 |
| inventory.json | 已有包管理器元数据和登记路径快照 | 运行采集脚本生成 |
| policy-source.json | 本机规则来自哪个仓库与内容指纹 | 初始化脚本维护 |

## 验证层次

`unverified` 表示尚未核实；`metadata` 表示仅核对安装元数据或路径；`basic` 表示完成启动、版本或基础检查；`workflow` 表示完成所述真实流程。日期和范围必须是实际检查所得。

已安装、已配置、已验证和当前会话可调用分别判断。当前会话可调用不能作为跨会话永久状态保存；需要时查看该客户端的实际工具列表和调用结果。

## 刷新

```sh
python3 ~/Developer/machine/refresh-inventory.py
```

默认写入该脚本部署的 machine 目录；从仓库 scripts 目录运行时，默认写入当前用户的 `~/Developer/machine`。自定义位置用 `--machine-dir` 明确指定。

脚本只查询已有 Homebrew、npm 全局、uv 和 pipx 工具元数据，以及登记的命令和路径。没有某个管理器时记录该条件，不安装它。它不遍历所有业务文件，不读取密钥，不执行目标扫描，也不把目录存在自动登记为已验证。

更新 `tools.json` 后再刷新，以免阅读索引和主登记不一致。本机状态文件不要加入公开仓库，即使当前没有密钥，也可能包含用户名、项目和使用痕迹。
